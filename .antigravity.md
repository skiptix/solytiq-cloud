Solytiq Cloud is a self-hosted, full-stack productivity suite: task lists, project timelines, file
sharing, shared workspaces, a GPS/GPX route planner, and an AI assistant. The stack is React
19 + Vite (frontend), Express + TypeScript (backend), PostgreSQL 16, and Nginx —
orchestrated with Docker Compose.

Version Number
The current version is displayed at the bottom-left of the sidebar in
frontend/src/components/Sidebar.tsx.
On every deploy / release, update the version string in that file — search for the v1.14.0
literal (it appears in two places, for the expanded and collapsed sidebar states) and bump both.
Use semantic versioning: patch for small fixes, minor for new features, major for breaking
changes.

Development Setup

Prerequisites
● Docker + Docker Compose (recommended for full stack)
● Node.js 22+ (for local frontend/backend development)
● PostgreSQL 16 (if running backend without Docker)
Running with Docker Compose (recommended)
cp .env.example .env # fill in POSTGRES_PASSWORD, JWT_SECRET
docker compose up --build
Frontend is served at http://localhost (port 80 via Nginx).
Running locally without Docker
Backend:
cd backend
npm install
npm run dev # ts-node-dev with --respawn, port 3001
Frontend:
cd frontend
npm install
npm run dev # Vite dev server, port 5173 with HMR

Backend Conventions
Database
● No ORM: All queries use raw SQL via the pg client.
● Schema Migrations: Run automatically at startup inside runMigrations().
● ID Types: Task IDs are BIGINT. Most other entity IDs are VARCHAR(100) or UUID.
Core Data Model
Table Purpose / key columns
users id UUID, username, email, password_hash
tasks id BIGINT, source, list_id, workspace_id
Authentication
● JWT tokens verified via verifyToken in middleware.ts.
● TOTP 2FA: Handled by otplib.
● Passwords are hashed with bcryptjs.
Rate Limiting
● apiLimiter — 300 req / 15 min
● authLimiter — 10 req / 15 min

Frontend Conventions
State Management
All shared state lives in Zustand stores under src/store/.
Store Contains
useAppStore Tasks, lists, folders, timelines. Loader:

loadFromApi

useAuthStore Current user, JWT token, 2FA state
Routing
● Authenticated Routes: /dashboard, /list/:listId, /timeline/:timelineId
● Public Routes: /login, /setup, /share/:token

Security Notes
1. IDOR: All DB queries must filter by user_id = $userId from the JWT.
2. JWT_SECRET: Must be a strong random secret.
3. Upload Validation: Validate MIME types and extensions server-side.

Key Architectural Decisions
● Migrations in Code: Add additive migrations to runMigrations().
● Raw SQL Over ORM: Keeps queries explicit.
● Soft Deletes: Route to trash* tables with a 30-day expiry.
● Workspace Scoping: All core entities are tied to a workspace_id.
